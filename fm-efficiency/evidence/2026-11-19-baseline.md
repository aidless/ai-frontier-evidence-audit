> 纪律：arXiv 编号必须 abs 页「号—题—作者」一致才算核实；官方通稿数字只作**事件**证据，不作**性能**证据；
> 自我报告（self-report）与独立测量分开记；同一断言两次核验不一致时列出冲突，不开第三条路。

## 核验方法

1. 每条断言反查到**一手载体**：arXiv abs 页 / 期刊 DOI 页 / 官方博客 / 校方或机构通报。
2. 判定四档：`已核实`（一手载体与断言一致）、`已核实·口径受限`（事实成立但数字口径需改写）、`事件已核实·无一手论文`（发布真实、性能数字仅官方口径）、`未核实`（载体不可达或找不到出处）。
3. 否定证据（"某机构并未做某事"）同样要求一手载体，单独立一条。
4. 冲突项单列「冲突与存疑」，不静默取一个。

## 未核实 / 冲突与存疑

- **RangeSWA 的实际增益**：摘要无数值，正文未取，暂不可引用。
- **RSI 的长期稳定性**：现有证据全是限定场景（代码优化、内核调优、矩阵乘法），无跨代际持续性数据。

## 本项目的证据缺口（下一步取证目标）

1. **「免训练扩上下文」缺同底物对照**：LongLLaDA / MPPA / RangeSWA 三条路线各自报增益，无人把三者放在同一 base、同一评测、同一预算下比。
2. **RSI 的净增益未扣成本**：DGM 的 20→50 是分数，但搜索/验证/回滚的算力成本未归一，无法判断是否值得。
3. **AROMA 的解释力-能量悖论**：89.82% vs 9.52% 说明「找对方向」不等于「改对权重」，该悖论是否为所有冻结方向方法的通病，未测。
4. **工程协同缺可测指标**：模型-编译器-算子协同的收益通常被归入「系统优化」，与模型侧增益不可分离。

## 引用纪律（写稿时强制）

- 表格里 `事件已核实·无一手论文` 的条目，正文只能写「发布/宣布」，不能写「证明/达到」。
- `已核实·口径受限` 的条目，数字必须带口径限定语（自我报告 / 论文自选任务 / 厂商通稿）。
- `未核实` 的条目在正式稿中删除，或标 `[待核]` 并在提交前复查。
