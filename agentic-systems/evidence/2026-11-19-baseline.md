# 证据核验基线 — 智能体系统：协同、协议与可审计失败

> 项目：`agentic-systems` ｜ 核验日：2026-11-19 ｜ 版本：evidence-baseline v1
> 来源：2026-11-19 六方向并行检索（4 路子代理 + 主会话独立验号），原始综述由用户提供。
> 纪律：arXiv 编号必须 abs 页「号—题—作者」一致才算核实；官方通稿数字只作**事件**证据，不作**性能**证据；
> 自我报告（self-report）与独立测量分开记；同一断言两次核验不一致时列出冲突，不开第三条路。

## 核验方法

1. 每条断言反查到**一手载体**：arXiv abs 页 / 期刊 DOI 页 / 官方博客 / 校方或机构通报。
2. 判定四档：`已核实`（一手载体与断言一致）、`已核实·口径受限`（事实成立但数字口径需改写）、`事件已核实·无一手论文`（发布真实、性能数字仅官方口径）、`未核实`（载体不可达或找不到出处）。
3. 否定证据（"某机构并未做某事"）同样要求一手载体，单独立一条。
4. 冲突项单列「冲突与存疑」，不静默取一个。

## 未核实 / 冲突与存疑

- **MCP 首发日 2024-11**：未见一手公告页，仅有二手叙述。可引用「2024 年末」但不宜写具体日。
- **WorkflowArena 的机构归属**：仅拿到搜索摘要级署名，abs 页作者单位未逐条核对，暂不写「某实验室出品」。
- **arXiv:2611.19925 / 2610.05831 / 2609.32081**：搜索结果级线索，未验号，不进稿。

## 本项目的证据缺口（下一步取证目标）

1. **终止延迟缺机制层解释**：38–82% 早解晚停的现象已量化，但「为什么不停」只有假设（自我怀疑、验证循环、scaffold 终止信号缺失），无干预实验——本项目第一切入点。
2. **遗忘修复缺与基线的配对**：Agentic-OPD 的 +7.4 未给出与「保留全部 checkpoint 朴素集成」的配对对照，净增益不明。
3. **欺骗缓解缺独立复现**：e-PoG 的 +26.0% 为自报，且与 2505.01420 的「未达担忧水平」并存，需第三方在同底物上重测。
4. **协议标准化缺因果证据**：MCP/A2A 的下载量与组织数只能证明采用广度，不能证明「通用语言」降低了协同失败率。

## 引用纪律（写稿时强制）

- 表格里 `事件已核实·无一手论文` 的条目，正文只能写「发布/宣布」，不能写「证明/达到」。
- `已核实·口径受限` 的条目，数字必须带口径限定语（自我报告 / 论文自选任务 / 厂商通稿）。
- `未核实` 的条目在正式稿中删除，或标 `[待核]` 并在提交前复查。
